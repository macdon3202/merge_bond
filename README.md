# MergeBond

MergeBond is a competitive implementation-bounty dApp for GenLayer. A sponsor seals an exact GitHub issue and a deterministic acceptance policy, locks GEN, and opens a short claim window. Developers submit merged pull requests. The first claim that passes canonical GitHub provenance gates, exact-CI binding, production-and-test path checks, and independent semantic prover/falsifier consensus reserves the payout.

## Why GenLayer

GitHub can authoritatively establish repository, issue, PR, merge, changed-file and check-run facts. It cannot determine whether a code change substantively satisfies natural-language acceptance criteria or whether a plausible patch hides an omission or security regression. MergeBond assigns only that bounded semantic comparison to GenLayer validators; deterministic contract code controls lifecycle, custody, replay protection and payout eligibility.

## Architecture

```text
Sponsor wallet
  -> create policy-bound DRAFT
  -> seal exact GitHub Issue bytes
  -> fund exact GEN amount
  -> OPEN competitive pool

Developer wallets
  -> register authenticated sender
  -> submit unique merged PR number

Any wallet
  -> trigger evaluation
     -> GitHub-controlled API facts
     -> exact issue digest and base repository/branch
     -> production path + regression path
     -> named successful check on exact head SHA
     -> validator prover/falsifier over criteria and patches
  -> first valid claim reserves payout

Winner or sponsor
  -> withdraw claimable payout/refund
```

The deployer is not stored and has no authority. The sponsor is the authenticated sender that creates a bounty; a sponsor cannot claim its own bounty. Evaluation and expiry are permissionless, so a reviewer may use any funded StudioNet wallet.

## State machine

```text
DRAFT -> SEALED -> OPEN -> RESERVED -> PAID
                    |
                    +-> EXPIRED_REFUNDABLE -> PAID
```

Wrong or unexpected attached value is never silently added to a bounty. It is credited to a sender-specific refund ledger and can be withdrawn. Every funded nonterminal state has either a bounded expiry path or a claimable owner.

## Frontend

```powershell
cd frontend
Copy-Item .env.example .env.local
# Set VITE_CONTRACT_ADDRESS to the exact StudioNet deployment.
npm run dev
```

The UI accepts an injected browser wallet. It does not contain private keys or fixed role addresses. Every write:

1. validates the active contract version;
2. normalizes either a hash string or `{ txId }` SDK response;
3. waits for `FINALIZED`, affirmative consensus and successful execution;
4. reads the exact returned bounty or claim ID;
5. reports success only after authoritative state matches the expected transition.
